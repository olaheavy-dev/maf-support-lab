## What I built

- **`src/python/`, a uv project:**
  - `pyproject.toml` declares the direct dependencies with exact pins: `agent-framework-core` 1.25.0, `agent-framework-anthropic` 1.0.0b261106 (prerelease, unavoidable), `anthropic` 1.17.0 (latest 1.x; MAF requires `<2`), FastAPI, Uvicorn, Pydantic and pydantic-settings, plus a dev group (pytest, httpx, ruff, pyright).
  - `uv.lock` holds the full resolved tree (42 packages) with hashes.
  - The pinned prerelease resolves without any prerelease setting. An explicit `==` pin is enough, and uv 0.13.7 had deprecated the setting I first tried.
  - **The owner chose** FastAPI + Uvicorn, and pyright (strict).
- **Host shell (`support_agent/`):**
  - `settings.py`: pydantic-settings from the environment (`MODEL_PROVIDER__MODE`, `ANTHROPIC_API_KEY`, `IDENTITY__DEVELOPMENT_CUSTOMER_ID`, `APP_ENVIRONMENT`), validated at startup. Fake mode needs nothing; live mode needs a model and a key; development needs the customer id. The key is a `SecretStr`, and errors hide their inputs.
  - `identity.py`: the same boundary as .NET. A fixed `DevelopmentPrincipalSource` in development, `NoIdentityProvider` (fail closed) elsewhere, and requests reach identity only through `get_principal`. Tests override it with FastAPI `dependency_overrides`, a server-side point no client can reach.
  - `app.py`: `create_app(settings)`, `/health`, `/alive`, `/dev/whoami` (development only); no docs or OpenAPI routes. `__main__.py` runs it standalone.
  - `resources.py`: **the lifespan owns every long-lived client** and closes each once, newest first, at shutdown.
- **No .NET in Python:** a ruff `banned-api` rule (TID251) forbids `clr`/`pythonnet`, and `test_boundaries.py` checks every module's imports.
- **Aspire:**
  - `Aspire.Hosting.Python` 13.6.4;
  - `AddUvicornApp("support-api-python", "../src/python", "support_agent.app:app").WithUv(["sync","--locked"])` with development settings and a `/health` check.
- **CI:**
  - a new `python` job (setup-uv v10.3.3 pinned by SHA, uv 0.13.7, Python 3.15.2): `uv sync --locked`, ruff check, ruff format check, pyright, pytest;
  - the required `repository-checks` aggregate now needs it.
- **Dependabot:** a `uv` ecosystem entry for `/src/python`, grouped as agent-framework, web, and dev tools.
- **Docs:** `src/python/README.md` (running standalone and with Aspire, configuration, identity, who cleans up, checks) and the version baseline rows.
- **Fixed along the way:** the planning tests copied the whole repository for each test, now including `.venv`. Locally that took 81 s; it now skips build and environment folders and takes 3 s (CI was unaffected).

## Course versus current implementation

| Course (Python) | Here | Why |
| --- | --- | --- |
| `common/config.py` reads env vars ad hoc | Typed, validated settings; fails at startup | Misconfiguration is found before serving |
| A script-style `app.py` | An ASGI app factory plus a lifespan that owns resources | Testable, and clean shutdown of clients |
| No identity boundary | A server-owned, fail-closed principal, the same as .NET | Model or client input never becomes identity |
| Run directly | Run standalone or through Aspire (`uv sync --locked`) | One orchestrated dev environment; the logic stays in Python |

## Tradeoff I can defend

**Exact pins in `pyproject.toml` plus a lock file.** Ranges in `pyproject.toml` with a lock would let `uv lock --upgrade` move freely. Exact pins make every version change a visible diff in two files, which matches the policy of recording versions deliberately. Dependabot (the uv ecosystem) proposes the bumps. The cost is more update PRs.
