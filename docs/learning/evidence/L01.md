## Interview answers (assistant-drafted reference)

1. *How do you establish that a tutorial is compatible with the SDK you selected?* Pin the tutorial's commit and read its manifest to see which versions it targeted. Read the release notes between those versions and yours for breaking changes. Where the docs and the code disagree, the release-tagged source wins. Then prove it with the smallest compile, import, or run check. Here, the course targets MAF 1.19; 1.28 made workflow sensitive-data capture a no-op and renamed workflow spans, so copying the course verbatim would compile but silently lose behavior.
2. *Why can core be released while DevUI or hosting remains prerelease?* Packages are versioned and stabilized independently. Core abstractions (agents, tools, workflows) get a stable API commitment first; developer tools and protocol hosting adapters change faster and depend on evolving external protocols. In this baseline, `Microsoft.Agents.AI` is 1.28.0 stable while DevUI is preview and Hosting.OpenAI is alpha. So we use prereleases only in development-only components, and the production path stays on stable packages.

## Tradeoff I can defend

Default to `claude-haiku-5-5` rather than a larger model. Routing and tool calls over small fixtures don't need deep reasoning, and the cost is roughly 20 times lower than Sonnet. The risk is lower accuracy on ambiguous triage. That is handled by validated structured output with a controlled fallback (L07), plus an evidence-based switch to Sonnet if needed.
