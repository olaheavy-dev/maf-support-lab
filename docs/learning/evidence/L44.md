# L44 - Move the .NET stack to the .NET 11 runtime

> **Authorship:** The assistant (Claude Code) implemented this ticket and drafted this note. Per the owner's choice, interview questions and tips are given in chat rather than recorded here.

## What I built

- **`global.json`:** SDK 10.0.403 → **11.0.100**, still with patch-only roll-forward. CI's `setup-dotnet` steps read this file, so CI follows without workflow changes.
- **`Directory.Build.props`:** `net10.0` → **`net11.0`**. Every project inherits it.
- **`Directory.Packages.props`:** `Microsoft.AspNetCore.Mvc.Testing` 10.0.14 → **11.0.0**. It is the only package versioned with ASP.NET itself.
  - Microsoft.Extensions.AI and its evaluation packages stay on **10.11.0**, because MAF 1.28.0 depends on them.
  - OpenTelemetry, Anthropic, Aspire 13.6.5 and Microsoft.Data.Sqlite 11.0.0 are versioned independently and needed no change.
- **Lock files regenerated.** Besides `Mvc.Testing`, the main change is **package pruning**. On .NET 11, NuGet drops packages whose contents now ship inside the shared framework, such as several `Microsoft.Extensions.*` 10.0.x abstractions. They come from the runtime instead.
- **Analyzer CA2026 fixed in 6 places, not suppressed.** `JsonDocument.Parse(...).RootElement` returns an element whose pooled `JsonDocument` is never disposed. `JsonElement.Parse(...)` returns a standalone element.
  - **App:** `TriageAgentFactory.ModelSchema`. It used `.Clone()`, which copied the element but still left the original document undisposed.
  - **Tests:** `ApiClient`, `SseClient` (2), `TurnSubmissionSafetyTests` and `CancellationTests`.
  - Every other `JsonDocument.Parse` in the repository is already in a `using` block, so it is disposed correctly.
- **Docs:** ADR 0001 (runtime row with the support dates, the `net11.0` heading, and why the evaluation packages stay on 10.11), `docs/testing.md`, `src/dotnet/README.md`, and two notes and links in `docs/sources.json`.

## Course versus current implementation

| Course | Here | Why |
| --- | --- | --- |
| An older .NET runtime | .NET 11 (STS) | The official release index lists end of support for both 10.0 (LTS) and 11.0 (STS) as **2028-11-14**. The latest-stable rule therefore picks 11.0 at no support cost. |
| `JsonDocument.Parse(...).RootElement` | `JsonElement.Parse(...)` | The newer API returns a standalone element, so no pooled document is left undisposed (CA2026). |

## Tradeoff I can defend

**Moving to an STS runtime.** The usual reason to stay on LTS is a longer support window. Here that reason doesn't apply, because STS support grew to 24 months and both releases end on the same day. The cost is that .NET 12 (LTS, November 2027) will be the next move, and must happen before 2028-11-14. Staying on 10 would carry the same deadline.

**Keeping Microsoft.Extensions.AI on 10.11.** Its version number looks tied to the runtime, but it isn't. MAF 1.28.0 is built against it, and moving it ahead of MAF risks a mismatch. It moves when MAF does.
