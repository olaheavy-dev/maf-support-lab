# L22 - Verify browser compatibility with the established API contract

> **Authorship:** The assistant (Claude Code) implemented this ticket and drafted this note. Per the owner's choice, interview questions and tips are given in chat rather than recorded here.

## What I built

**The owner's choices:** Playwright with Chromium; a tiny zero-dependency Node proxy; the backend alias in the path, stored with the conversation id; and the probe proxy in the AppHost now.

- **`frontend/probes/proxy/server.mjs`:** serves the probe page and forwards `/api/{alias}/v1/...`.
  - **Aliases** are a fixed allowlist (`dotnet` → `support-api-dotnet`, `python` → `support-api-python`). Addresses come only from Aspire's `services__<resource>__http__0`, or `__https__0` when that's all there is.
  - **What's forwarded:** only `content-type`, `accept` and `content-length` go up; the response is piped back unbuffered. The upstream gets its own loopback `Host`.
  - **Errors:** an unknown alias, an encoded URL in its place, or `..` gets a contract `404`; an unreachable backend gets a contract `503 service_unavailable`.
  - **`GET /api/backends`** returns aliases, never addresses.
- **`frontend/probes/proxy/public/`:** the probe page.
  - **Streams** are read with `fetch` and a stream reader (POST, so not `EventSource`), with `reply.reset` applied and `turn.final` treated as authoritative.
  - **Approvals:** approve or reject from the pending list.
  - **Refresh:** `{alias, conversationId, lastTurnId}` is kept in `sessionStorage`. After a refresh the page re-reads the conversation (`pending_approvals`, `active_turn_id`) and recovers the last turn by its id.
  - **Rendering:** `textContent` everywhere. The backend picker is locked while a conversation is open.
- **`tests/contract.spec.mjs` (17 tests):** the same 7 checks per backend, plus 3 shared.
- **AppHost:** a `browser-probe` resource (`AddNodeApp`, `WithReference` to both backends, health check), using `Aspire.Hosting.JavaScript` (13.6.5; see the Aspire upgrade below).
- **CI:** a `browser` job (Node 26.13.1, `npm ci`, Chromium), now required through `repository-checks`. Dependabot covers npm for `frontend/probes`.
- **Docs:** `docs/decisions/0006-browser-integration.md` (the decisions, and the stretch: how a refreshed browser discovers a pending approval), plus `contracts/README.md`, `docs/testing.md`, the 0001 version rows and `frontend/probes/README.md`.

## The contract held: no breaking change

Every probe passed against both backends with the contract unchanged: streaming, pausing for approval, refresh, recovery and errors. No schema or adapter change was needed, which is the outcome the alignment rule hoped for.

## What Aspire showed (and the fix)

- **The problem:** the first run under Aspire listed only `dotnet` in `/api/backends`. Aspire serves the Python backend over **https** with its development certificate, so it passes `services__support-api-python__https__0`, not `__http__0`.
- **The fix:** the proxy accepts `__https__0` when no `__http__0` exists, and uses `node:https` for it. Aspire also sets `NODE_EXTRA_CA_CERTS` for the Node resource, so Node trusts the certificate without turning verification off. A test pins the variable precedence.
- **Re-checked through Aspire:** the proxy listed both aliases; it created a conversation on each backend (`backend` = `python` / `dotnet`); `GET` on its own alias returned `200`, and on the other alias `404`.
  - I sent no model turns through Aspire, because the owner's .NET user-secrets select Live mode. The same flows ran in Playwright against both real backends in fake mode.
- **A slip of mine:** one inspection command filtered environment names for "TLS", which also matched an `OTEL_EXPORTER_OTLP_*` line. It printed that run's dashboard OTLP API key into local tool output. It wasn't stored or used, and it stopped working when the Aspire session was stopped right after. Later checks printed nothing from the environment.

## Review and CI fixes (PR #97)

- **CI: the `browser` job couldn't start the proxy.**
  - Playwright starts each web server through `/bin/sh`. On Ubuntu that's dash, which silently drops environment variables whose names contain `-`, so `services__support-api-dotnet__http__0` never arrived. macOS's shell keeps them, so it passed locally.
  - Aspire also sets shell-safe names (`SUPPORT_API_DOTNET_HTTP`, `SUPPORT_API_PYTHON_HTTP`). The proxy now reads those first and keeps the `services__…` form as a fallback, and the test config uses them. A test pins the order.
- **Codex P2: an inherited property as an alias crashed the proxy.**
  - `targets["constructor"]` found `Object.prototype.constructor`. That passed the allowlist check, and `http.request` then threw outside the error handler, so the whole process exited.
  - Fix: the targets object has no prototype, and lookups use `Object.hasOwn`.
  - The binding test now sends `constructor`, `__proto__` and `tostring` (all `404`) and checks the proxy still answers. Restoring the old lookup crashes the proxy, and every later test fails.
- **Codex P2: a reload during a running write turn lost the approval buttons.**
  - The backends list an approval only once its turn is stored, so the first conversation read after the reload was empty, and recovery never re-read it.
  - Fix: the page re-reads pending approvals after recovering a turn.
  - New test: Playwright's `page.route` shows the page the mid-turn conversation on its first read (turn active, no approvals). The approval then appears once the turn is recovered. Removing the re-read fails it.
- **Aspire upgrade: 13.6.4 → 13.6.5** (the owner's choice: in this PR).
  - The `nuget-vulnerabilities` audit flagged GHSA-f7vh-h5g3-7jrh (CVE-2026-120006, high, elevation of privilege). It came from `Aspire.Hosting` and `Aspire.Hosting.AppHost`, which the `Aspire.AppHost.Sdk` version brings in, so Dependabot's #83 (only `Aspire.Hosting.Python`) wouldn't have cleared it.
  - Now `Aspire.AppHost.Sdk`, `Aspire.Hosting.Python` and `Aspire.Hosting.JavaScript` are all 13.6.5. `dotnet list package --vulnerable --include-transitive` reports none, and the build has 0 warnings.
  - Through Aspire 13.6.5, all four resources ran `Running/Healthy`, and the proxy created a conversation on each backend (`201`).

## Course versus current implementation

| Course | Here | Why |
| --- | --- | --- |
| DevUI as the way to talk to agents | A probe page against the versioned contract, and DevUI kept as a developer tool | A product talks to a contract, not to a framework's developer UI |
| Approval decided inside one request | Pause, rediscover after a refresh, decide later, recover by id | Real users refresh, lose connections and come back |

## Tradeoff I can defend

**The browser holds the conversation's backend alias; the proxy holds no map.** A proxy-held map would make binding unforgeable from the browser, but then it's proxy state that must be stored, shared across instances and cleaned up. Holding the alias in the browser is safe here because the backends share nothing: a wrong alias simply finds no conversation (`404`), and ownership is still enforced by each backend. The cost is that the client must keep `{alias, id}` together. That's documented in 0006, and the picker is locked while a conversation is open.

## Remaining questions

- **Unbuffered forwarding** is implemented (`pipe` plus `flushHeaders`), but the fake model finishes too quickly to prove timing in a test. Measuring first-delta latency through the proxy would need a slow model, or the live check in L23.
- **One browser:** only Chromium was tested (the owner's choice). Firefox and WebKit can be added to the Playwright projects when the product UI exists.
