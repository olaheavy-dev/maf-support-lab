# L21 - Verify cross-language application contracts and document SDK decisions

> **Authorship:** The assistant (Claude Code) implemented this ticket and drafted this note. Per the owner's choice, interview questions and tips are given in chat rather than recorded here.

## What I built

- **Owner's choices:** black-box probes over real HTTP, written as a Python runner in `contracts/probes/`.
- **`contracts/probes/run_probes.py`:** starts the real .NET and Python servers in fake mode, with no credentials and no network.
  - Each backend runs as **two processes** on one SQLite file: one as `CUST-1001` and one as `CUST-1002`. Both stores load a conversation from SQLite and then check its owner, so a cross-customer request really exercises the server's ownership check. It can't pass just because the record is missing.
  - It sends the same **29 requests** to both backends, covering:
    - **conversations:** create, read, unknown fields, malformed JSON, another customer's, a missing one;
    - **turns:** answer, replay, a reused id, another customer posting, read, cancel finished and unknown, invalid body, another customer's order, an ineligible write, a model failure;
    - **an approval-gated write:** awaiting, pending, another customer's operation and decision, a wrong operation, approve, committed, a repeat, a different decision afterwards;
    - **a full SSE stream.**
  - Every response is validated against the contract schemas, and problems must be `application/problem+json`.
  - Probe-level rules are checked too: a foreign record looks exactly like a missing one; a replay is identical; the stream's deltas after the last reset equal the final text; the final event equals the stored turn.
  - The results are then normalized and must be **equal** between the backends. Runtime ids and times become stable placeholders, wording and `detail` become `<text>`, and `errors[]` must be present but its wording is free.
  - `ALLOWED_DIFFERENCES` is empty, and a test keeps it that way by default.
- **`contracts/tests/test_probes.py` (10):** the runner's own logic. Ids are normalized but fixture ids and business values are kept; an ownership regression and a missing field are reported; a broken stream is a contract violation.
- **CI:** a `cross-backend` job (both toolchains, locked), now part of the required `repository-checks`.
- **`docs/decisions/0004-sdk-comparison.md`:** native SDK choices, resource lifecycle, known implementation differences and their contract effect (none, or wording only), the compatibility evidence, and what would decide an SDK for a team.

## Drift the probes found (and the fixes)

The first run: both backends passed the contract on all 29 probes, but they differed in three ways:

| Drift | Decision | Fix |
| --- | --- | --- |
| A failed turn had a `route` in .NET, none in Python | Align. Both are schema-valid, but clients should see the same thing, and the route is useful. | Python keeps the route from triage's `routed` progress event (`api.run_turn`). New test `test_a_turn_that_fails_after_triage_still_reports_its_route`. |
| .NET's invalid **create** body had no `errors[]` | Fix .NET. The contract says invalid_request "lists JSON pointers". | It now lists `""` for a non-object or malformed body, or `/<first key>`, escaped per RFC 6901. New theory `An_invalid_create_body_lists_the_offending_pointer` (4 cases, including `/a~1b~0c`). |
| Python used `"/"` for the whole body | Fix Python. RFC 6901's whole-document pointer is `""`; `"/"` means a key named empty-string. | `contract.errors` and the invalid-JSON problem use `""`; the test expectations were updated. |
| `detail` wording, and the validator's error messages and count | Allowed: human text. Recorded in 0004. | Normalized (`<text>`, `<errors>`). |

**One mistake of mine, caught by the .NET suite:** my first .NET fix used `EnumerateObject().FirstOrDefault()`. On an empty `{}` that returns a default `JsonProperty`, whose `Name` throws, so every conversation create returned a 500 and 146 tests failed. Rewritten with an explicit enumerator; all pass.

- **A known regression fails** (acceptance criterion, and the stretch exercise; each reverted):

  | Regression | What the probes report |
  | --- | --- |
  | Python `find_owned` stops checking the owner | `python: FAILED: another customer's conversation must look exactly like a missing one` |

  Why the second one fails without any expectation written for it: the problem schema ties each code to its status. A wrong status is a contract violation before the two backends are even compared.

## Course versus current implementation

| Course | Here | Why |
| --- | --- | --- |
| Two separate samples, compared by reading them | One contract, checked in each backend's tests and by a black-box comparison of the running servers | "Looks similar" isn't evidence; status codes, field presence and stream framing drift silently |
| SDK differences undocumented | Every difference listed with its contract effect (0004) | So a reviewer can tell an idiom from a broken rule |

## Tradeoff I can defend

**Black-box probes in addition to in-process tests.** Each backend already ran the 19 shared scenarios, but in-process tests compare each implementation to *expectations*, never to each other. They didn't catch any of the three drifts above, because each backend's tests encoded that backend's own choice. The probes cost a CI job with both toolchains (a couple of minutes) and some process management. In return, they test what a client actually sees, through real HTTP, real hosts and real SSE framing.

## Remaining questions

- The probes cover one representative path per area, not all 19 scenarios. The scenarios stay in each backend's own suite; E08 (L16) will build the shared runner.
- Wording is deliberately not compared. If clients ever display `detail` verbatim, the contract should standardize it.
- One process per backend per customer works because the probes are sequential. The in-process turn lock (an L11 carry-over) still means "one process per database file" for concurrent use.
