# L30 - Integrate Microsoft .NET evaluation APIs with local checks

> **Authorship:** The assistant (Claude Code) implemented this ticket and drafted this note. Per the owner's choice, interview questions and tips are given in chat rather than recorded here.

## What I built

- **Packages** (evaluation project only): `Microsoft.Agents.AI` 1.28.0, which has MAF's local evaluation, and `Microsoft.Extensions.AI.Evaluation` 10.11.0, the abstractions it builds on. 10.11.0 is the version MAF 1.28.0 depends on; 11.0.0 pairs with .NET 11, still a release candidate. No application project references either package.
- **Verified against the pinned release:** I read the release-tagged sample (`dotnet-1.28.0`, `Evaluation_CustomEvals`) and the 1.28.0 API documentation. The API includes `EvalItem`, `ExpectedToolCall`, `EvalChecks.ToolCallArgsMatch()` (a method returning the check, not a field), `FunctionEvaluator.Create`, `LocalEvaluator`, and two `AgentEvaluationExtensions.EvaluateAsync` overloads: one with queries (runs the agent), and one with recorded `AgentResponse`s, documented as "without re-running the agent".
- **The capture contract** (`evaluations/schemas/evaluation-capture.schema.json`): a normalized recorded turn, holding
  - the query, and the response messages with `function_call`, `function_result` and `approval_request` contents;
  - the tools (with `writes`), the context references, and the case and dataset version.

  `Native/Captures.cs` converts MAF messages to captures and back, to `AgentResponse` and `ExpectedToolCall`.
- **Dataset schema 1.2:** `expected_tool_calls` on 11 cases, in canonical snake_case, mapped to the .NET tools' names by the adapter. **Run schema 1.2:** an `evidence` link and case-level `checks`.
- **`Native/FakeSupportAgent.cs`:** a MAF `ChatClientAgent` over a scripted MEAI chat client that counts its calls.
  - Its tools have the .NET backend's names and parameters and read the shared fixtures for one customer; reads check ownership.
  - The writes are `ApprovalRequiredAIFunction`s that throw if ever run.
- **`Native/SupportChecks.cs`**, through `LocalEvaluator`:
  - MAF's `ToolCallArgsMatch`;
  - `writes_wait_for_approval`, `no_unexpected_writes`, `record_ids_are_grounded`, `cites_found_record`.
- **Commands:**
  - **`native record`:** MAF's `EvaluateAsync(queries, …)` runs the fake agent and saves 11 captures to `evaluations/recordings/`.
  - **`native evaluate`:** `EvaluateAsync(responses, queries, …)` scores the captures. It **throws if the model was called even once**, refuses captures recorded for an older dataset version, and writes run documents with dataset and scorer versions and an evidence link per case.
- **CI:** `cross-backend` runs `native evaluate`. `compare` now leaves native runs out of the backend comparison.

## What the native evaluation found

1. **MAF 1.28.0's `ToolCallArgsMatch` doesn't see paused writes.** In a live `EvaluateAsync(queries)` run, an approval-required tool call arrives as a `ToolApprovalRequestContent`, and the built-in check counts only `FunctionCallContent`, so `cancel_order` was reported as "not called". It's the same wrapper that hid the .NET stream's tool call in L29.
   - The capture keeps the call as `approval_request`, and the recorded evaluation gives it to the checks as the model's call.
   - So **`native evaluate` is the gate**, and `native record`'s scores are informational. Recorded in ADR 0004.
2. **A false positive in my grounding check.** "For example ORD-1234" is a format example, not a record. The two documented format examples are now allowed, while invented or leaked real ids still fail.
3. **An SDK difference:** the .NET tools' arguments keep C# names (`orderId`), while Python's are `order_id`. The datasets hold canonical names, and the adapter maps them. Recorded in ADR 0004.

- **Native tests cover:**
  - recorded responses scored with **0 model calls**;

- **Behaviour:** all 31 cases pass on both backends and agree; the baseline was regenerated for dataset 1.2.0.
- **Python evaluations:** 29 passed. Repository validation passes.
- **Mutation checks** (each reverted):

  | Mutation | Caught by |
  | --- | --- |
  | `native evaluate` uses the queries overload (re-runs the agent) | the model-call guard (the command test fails) |

## The stretch: one reply, two checks

`A_reply_that_drops_the_record_it_found_fails_only_the_citation_check` scores the same captured turn with every check, after changing only the reply text to "It is on its way.":
- `tool_call_args_match` **passes**: its evidence is the tool call (`get_order_status` with `orderId: ORD-1002`), which is unchanged.
- `cites_found_record` **fails**: its evidence is the reply text, which no longer names the order the tool found.

Each check can only judge the evidence it reads. Neither of them, nor any answer-format check, can show that a refund was *authorized*. That's the backend's gate, proven through its API by the L16 runner.

## Course versus current implementation

| Course | Here | Why |
| --- | --- | --- |
| Foundry-hosted evaluation in the samples | `LocalEvaluator` with domain checks: no service, no credentials | Deterministic and free to run in CI |
| Evaluate by running the agent | Recorded responses scored without re-running, guarded by a call counter | Evidence stays fixed; reruns can't change it or spend money |

## Tradeoff I can defend

**A fake agent instead of the backend's real one.** Running the actual support agent in-process would mean referencing the API project from the evaluation project, and its business gates would blur into the scores. The fake agent exercises MAF's evaluation orchestration with the same tool shapes, while the real backends are evaluated through their API by L16. The cost: native scores describe agent behaviour (tool choice, arguments, citation), not the production prompt. L32's live lane adds that.

## Remaining questions

- If a later MAF release makes `ToolCallArgsMatch` count approval requests, the normalization can go.
- The captures come from the fake agent. Capturing real backend conversations would need the backends to expose (sanitized) transcripts, which the contract deliberately doesn't do.
