# L33 - Generate Microsoft evaluation reports and separate CI lanes

> **Authorship:** The assistant (Claude Code) implemented this ticket and drafted this note. Per the owner's choice, interview questions and tips are given in chat rather than recorded here.

## What I built

- **Packages and tools** (evaluation project only): `Microsoft.Extensions.AI.Evaluation.Reporting` 10.11.0, and the `aieval` tool from `Microsoft.Extensions.AI.Evaluation.Console` 10.11.0 in `.config/dotnet-tools.json`.
  - Version 11.0.0 of both pairs with Microsoft.Extensions.AI 11, ahead of MAF 1.28, so 10.11.0 is selected.
  - The tool ships builds for .NET 8–10 only, so the manifest sets `rollForward: true` for the .NET 11 runtime.
  - The tool sends anonymous telemetry unless `DOTNET_AIEVAL_TELEMETRY_OPTOUT=1`; CI and the docs set it.
- **`report` command** (`Support.Evaluations/Reporting/`):
  - **`ReportCommand`:** reads every result document in a folder, checks it against its schema, and writes `ScenarioRunResult`s to a `DiskBasedResultStore` under one execution name. It refuses a broken document and refuses two results for one scenario. A JSON file that isn't a result document is left out, and the output says so.
  - **`ReportAdapter`:** maps without re-scoring.
    - Each check becomes a boolean metric, *failed* when it failed. This covers step checks from the behaviour runner and case-level checks from native evaluations.
    - An errored case gets an error diagnostic and no value. A skipped case is *inconclusive*.
    - Quality metrics carry the judge's number, its reason, the grounding context, and one fresh chat turn per judge call.
    - Tags carry run id, commit, backend, dataset, scorer and runner versions, model mode, provenance, usage availability, and estimates.
- **Quality lane schema 1.1:** each metric keeps the evaluator's per-call metadata (`eval-model`, `eval-duration-ms`, `eval-input-tokens`, `eval-output-tokens`, `eval-total-tokens`). The run states `response_cache: not used`. 1.0 documents are still read.
- **The run's exit code** is now one tested rule, `Cli.ExitCodeFor`: any failed or errored case gives 1, and skips alone give 0.
- **CI:**
  - The `cross-backend` job builds the report (HTML and JSON) after the evaluations, even when they failed, and uploads it with the results.
  - A new **`Quality (live, billed)`** workflow runs `quality --live` only on manual dispatch. It needs the `ANTHROPIC_API_KEY` secret and fails fast without it, and its concurrency group prevents two billed runs at once. It builds and uploads the report too.
  - The deterministic lanes are unchanged and remain the required gates.
- **Docs:** `docs/evaluations/reports.md` (lanes, what the report keeps, reproduce, curated summary), `evaluations/README.md`, `docs/evaluations/quality.md`, `docs/testing.md`, and ADR 0001's two rows.

## How the request flows

The evaluations write run documents to `evaluations/results/` (ignored by Git). Then `report --execution <name>` maps them into a reporting store, and `aieval report` renders `report.html` and `report.json` from that store. CI uploads all of it as the `evaluation-results` artifact. No step of the report starts a backend, agent or judge.

## Course versus current implementation

| Course | Here | Why |
| --- | --- | --- |
| Traces as the record of a run (chapter 6) | Run documents and a reporting store, with run ids, versions and provenance as tags | Comparable across runs and CI attempts, and reproducible from the documented commands |
| — | An adapter into `ScenarioRunResult` instead of re-running evaluators through `ReportingConfiguration` | The results are already scored. Re-evaluating would call models (or a cache) for no reason, and the report must never invoke an agent or judge. |

## Tradeoff I can defend

**No response cache in the live lane.** Reporting's response cache would make reruns cheaper and give "cached" turns to show. But a cached judge answer replays one sample of a nondeterministic judge, and the second run here already moved a mean by a quarter point. The lane stays fresh (`cacheHit: false`, `cache:not-used`), and the report says so. Caching could be added for a regression lane that wants stability over variability.
